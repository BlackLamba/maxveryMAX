# 01. Целевая аудитория

## 1. Основная целевая аудитория

Для MVP целесообразно сфокусироваться на пользователях **18–34 лет, живущих в городах и регулярно использующих цифровые сервисы для поиска информации и планирования свободного времени**.

Возрастной диапазон выбран как **продуктовая гипотеза**, а не как утверждение о том, что пользователи других возрастов не заинтересованы в городских активностях.

Выбор этой группы связан с тем, что молодые пользователи демонстрируют высокую вовлечённость в событийный досуг. По данным ВЦИОМ, в 2024 году различные мероприятия по месту жительства за последний год посещали **58% россиян**, среди пользователей в возрасте **18–24 лет показатель составлял 80%**, а среди **25–34 лет — 67%**. Таким образом, высокая вовлечённость в событийный досуг характерна для всего выбранного диапазона 18–34 лет, а не только для его младшей части. [ВЦИОМ — «Точки притяжения, или Событийный туризм-2024»](https://wciom.ru/analytical-reviews/analiticheskii-obzor/tochki-pritjazhenija-ili-sobytiinyi-turizm-2024?utm_source=chatgpt.com)

При этом проблема заключается не только в наличии свободного времени. По данным ВЦИОМ за 2025 год, **16% опрошенных сообщили, что у них есть свободное время, но они не удовлетворены тем, как его проводят**. ВЦИОМ отдельно характеризует эту группу как людей, которым сложно понять, чем и как наполнить свой досуг. [ВЦИОМ — «Досуг: хорошо, но мало!»](https://wciom.ru/analytical-reviews/analiticheskii-obzor/dosug-khorosho-no-malo?utm_source=chatgpt.com)

Таким образом, для продукта представляет интерес пользователь, который:

* хочет провести свободное время вне дома;
* рассматривает различные городские активности;
* не обязательно заранее знает, куда именно хочет пойти;
* готов использовать цифровой сервис для выбора;
* принимает решение с учётом нескольких ограничений одновременно.

## 2. Основные характеристики пользователя

Пользователь может иметь следующие ограничения:

| Параметр               | Пример                                                    |
| ---------------------- | --------------------------------------------------------- |
| Время                  | сегодня вечером, завтра, выходные                         |
| Продолжительность      | 1–2 часа, несколько часов                                 |
| Тип активности         | концерт, выставка, театр, лекция, мастер-класс, фестиваль |
| Интересы               | музыка, искусство, история, образование, развлечения      |
| Расстояние             | рядом с домом, в центре города, до 30 минут в пути        |
| Бюджет                 | бесплатно, до 1000 ₽, до 3000 ₽                           |
| Компания               | один, пара, друзья, семья                                 |
| Возрастные ограничения | 0+, 6+, 12+, 16+, 18+                                     |
| Формат                 | офлайн                                                    |

Конкретный набор параметров является **проектным решением для MVP** и требует проверки на пользовательском тестировании.

---

## 3. Вторичная аудитория

В дальнейшем продукт может быть расширен на другие группы:

* пользователей старше 35 лет;
* семьи с детьми;
* туристов;
* пользователей, планирующих досуг небольшой группы;
* пользователей с ограниченным бюджетом;
* пользователей, которым важна минимальная продолжительность мероприятия или небольшое расстояние.

Расширение аудитории не входит в обязательный объём MVP.

---

## 4. Почему не стоит ограничиваться только культурными событиями

На рынке уже существуют крупные информационные ресурсы, содержащие сведения о культурных мероприятиях.

Например, портал **«Культура.РФ»** объединяет афишу мероприятий по всей России и позволяет выбирать события по типу и тегам. На портале публикуются выставки, спектакли, концерты, мастер-классы, лекции и другие мероприятия. [Культура.РФ — «О проекте»](https://www.culture.ru/about?utm_source=chatgpt.com)

Следовательно, потенциальная ценность продукта заключается не в простом создании ещё одной афиши.

Основная задача — создать **слой выбора и сопоставления**, который помогает пользователю перейти от общего запроса:

> «Хочу куда-нибудь сходить»

к конкретному решению:

> «Вот несколько подходящих вариантов на сегодня с учётом моего времени, интересов, расстояния и бюджета».
